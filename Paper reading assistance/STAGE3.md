# 第三阶段：扫描论文、图式解读、本地模型与多篇对照

版本：`1.6.0-rc.1`。新增源码、依赖清单、测试、使用说明和安装包都位于 `Paper reading assistance/`。

## 安装和启动

要求 Node.js 22.13+ 或 24+。在仓库根目录运行：

```powershell
npm ci
npm --prefix "Paper reading assistance" ci
npm run reader
```

第二条安装该文件夹独立的 OCR 引擎和中英文数据。它不修改根依赖，不下载任何大语言模型权重。安装后识别过程使用本机 Worker 与 WebAssembly，不通过 CDN 加载识别引擎和语言数据。原 PDF 阅读与文字问答在未安装 OCR 时仍能使用。

Windows 也可以在依赖安装完成后双击本文件夹中的 `start-reader.cmd`。完整包为 [paper-reading-assistance-v1.6.0-rc.1.zip](release/paper-reading-assistance-v1.6.0-rc.1.zip)，附 [SHA-256](release/paper-reading-assistance-v1.6.0-rc.1.zip.sha256)；包中包含整个技能，解压后执行上述两条安装命令。

## 1. 本机扫描件 OCR

- 打开扫描版或混合版 PDF，在上方选择 English 或“中文 + English”。
- “识别当前页”只识别当前页，显示识别置信度和可编辑文本，核对后再保存。
- “识别待识别页”只处理可提取文字少于 20 字符的页面，逐页保存，可取消；已经完成的页面保留，下次继续未完成页。
- 原生文字页不会被静默覆盖；手动识别原生页时需确认替换。
- 保存后可翻译摘要、检索问答、选择 OCR 文字与添加高亮注释。词框以归一化页面坐标保存，缩放和重开后可恢复。
- 如果修改识别文本，旧的词框会丢弃，避免错误定位；可在阅读区“本页 OCR 文本”中复制修订后的文字。再次 OCR 可以重新建立词框。
- 低置信度不是失败，也不是准确率保证。数字、上下标、公式、复杂表格、歪斜扫描、双栏顺序需人工核对；OCR 不承诺数学公式的 LaTeX 还原。
- OCR 改动摘要后会清除旧译文，防止原文和译文不一致；旧注释若不再匹配原文会标记需复核。

OCR 数据保存在既有 `paper.json` 的 `pages[].ocr`，包含语言、置信度、文字位置、识别时间和是否修订，不修改原 PDF。中英文识别使用 Tesseract.js 及其语言数据。

## 2. 公式、图表与表格辅助解读

1. 在“模型设置”中选择真正支持图像的模型，勾选“所选模型支持图像输入”和图像发送授权；模型列表不代表视觉能力已自动验证。
2. 点击“框选公式 / 图表”，在 PDF 页上拖出区域。
3. 核对区域图像，选择公式/图表/表格，填写问题，并确认发送。
4. 阅读器发送这张区域图与至多 12000 字符同页文字，流式展示解读。
5. 结果保存在“图式解读”，可点击回到原页区域，并随笔记导出解释文本。框选图保存在本机论文目录，可在重开时查看。

服务端要求图像授权与单次发送确认，拒绝外部图片 URL、非 PNG、超出页面的区域、过大图像。只发送框选区域，不附整篇 PDF。区域图的像素上限为 2048 × 2048、400 万像素及 4 MiB，前端默认压至最长边 1600。

公式解读可说明符号、假设、适用条件，模型可给出 LaTeX；这不是形式化推导验证。图表解读应区分可见趋势和推测，不恢复不可见数据，不猜模糊符号或数值。模型能力不足或不支持图像时显示错误，不用伪造的文字结果代替视觉处理。

## 3. 本地大模型

支持两种协议：

| 类型 | 设置 | 说明 |
| --- | --- | --- |
| Ollama 原生 | 点击“使用本机 Ollama”，默认 `http://127.0.0.1:11434` | 调用 `/api/tags` 读取模型，`/api/chat` 流式问答；原生模式只允许回环地址 |
| 兼容接口 | 点击“使用本机 LM Studio”，默认 `http://127.0.0.1:1234/v1`，或填写已有兼容服务 | `/models` 检测，Chat Completions 问答，兼容 SSE 或完整 JSON |

先由用户自行安装模型运行器、下载所需模型并启动服务，再点“检测连接 / 读取模型列表”。阅读器不自动安装运行器、不下载模型、不修改服务配置。无需鉴权的本地服务可不填 Key。切换地址或协议不会向新服务沿用旧密钥。

文字问答用文本模型即可；图式解读还需视觉模型。Ollama 图像请求会转成原生 `images` 数组，兼容服务使用 `image_url` 数据地址。连接本机服务不等于服务本身没有云端转发，应核对运行器的模型来源与设置。

## 4. 多篇论文对照

导入并打开要对照的论文，确保已有提取文字或 OCR。点击“多篇论文对照”，选择 2–4 篇并提出问题。

对照按每篇最多 4 个相关片段构建上下文，可比较研究问题、方法、数据、实验条件、结果和局限。它不是对所有页的穷尽审计；没有依据时写未知，实验条件不同不直接排名。

引用使用 `[D1:p.3]`，同时校验论文编号和 PDF 物理页码。点击来源会打开对应论文的对应页；不匹配的来源标为“未核验来源”，单独 `[p.3]` 标为缺少论文标识。OCR 证据有 OCR 提示。引用只证明来源片段被提供，不证明模型结论正确。

完成的对照保存在数据根目录 `comparisons.json`，最多最近 100 条；重开可恢复、可导出 Markdown。取消或失败的部分结果不保存。已删除论文的历史对照仍保留原名称与片段，跳转会报告缺失；若要删除全部对照历史，请停止服务后删除数据目录中的 `comparisons.json`。

## 数据和权限边界

默认数据目录仍为 `~/.config/jiaoxiaoai-paper/`。OCR 完全在本机完成；视觉解读和多篇对照均使用用户配置并授权的模型，可能产生模型服务费用。图像与对照会比单段问答发送更多资料，应按论文的保密要求决定是否使用云端模型。

新增本地文件：`papers/<id>/visual-<id>.png` 为已解读的区域，`paper.json` 的 `visuals` 为解释与位置。删除论文会一并删除其图像。模型凭据和论文数据不进入源码和发行包。
